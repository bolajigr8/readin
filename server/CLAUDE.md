# ReadIn API (`project/server`) — Express 5 · TypeScript (ESM/NodeNext) · MongoDB (Mongoose 9) · zod 4 · pnpm

Production runs on **Node 20** (Dockerfile `node:20-slim`); the `tests/*.test.mjs` runner uses `node --experimental-strip-types`, which needs **Node ≥ 22.6 locally** (`node -v`). Consider bumping the Docker image to Node 22 LTS in a later stage (test first).

Deployed on Render (free, Docker, `autoDeploy`; env in the Render dashboard — never in git). Base URL `/api/v1`.
Read the root `CLAUDE.md` first. This file = server specifics.

## Commands
```bash
pnpm install
pnpm run dev            # nodemon
pnpm run typecheck      # tsc --noEmit  (must be clean)
pnpm run lint           # eslint — must show 0 errors (warnings allowed). Global `ignores` must be its own config object.
for t in tests/*.test.mjs; do node --experimental-strip-types "$t"; done
pnpm run test:e2e       # tests/e2e/run.mjs: real server (tsx) + in-memory MongoDB + fake Paystack/Resend + dead Redis (25 tests, ~15 s;
                        # first run downloads MongoDB ~650 MB). Never loads server/.env (DOTENV_CONFIG_PATH → tests/e2e/e2e.env).
npx tsx src/scripts/create-admin.ts     # env ADMIN_EMAIL / ADMIN_PASSWORD / ADMIN_NAME
npx tsx src/scripts/remove-test-users.ts [--confirm]   # NEVER `pnpm seed` on production
```
Local run needs a `.env` (copy `.env.example`; **never read/print/commit it**). Redis is optional locally only if limiters are configured to fail open — check `config/redis.ts`.

## Layout
`src/app.ts` (middleware order matters: health → body parsers/raw-body for webhooks → cors/helmet → `generalLimiter` → routers → HTML 404 for browsers → JSON 404 → error handler; **listen first, then connect DB**) · `routes/*.routes.ts` → `controllers/*.controller.ts` → `services/*` → `models/*.model.ts` · `middleware/` (auth `protect`, `admin.middleware`, rate limits, upload, errors) · `services/email/` (templates + Resend provider) · `services/pages/pages.ts` (branded HTML pages) · `scripts/` · `jobs/` (BullMQ conversion queue, disabled by `CONVERSION_ENABLED=false`).

## Key behaviours (don't break)
* **Auth**: bcrypt passwords, JWT access 15 min + refresh; `protect` loads the user from the DB each request and rejects disabled users; plan expiry applied via `expirePlanIfNeeded`. Login requires verified e-mail (403 + message containing “verify”). `POST /auth/resend-verification` is generic (no account enumeration) and throttled per account.
* **Google sign-in**: `/auth/google` verifies a Google ID token via Google's tokeninfo (`GOOGLE_CLIENT_ID[S]`); app currently has it switched off.
* **Entitlements**: `services/entitlements.logic.ts` is pure (unit-tested): admin → feature off → blocked → `freeForAll` → gift → premium → trial. Config `AppConfig('features')` is cached 30 s (billing 15 s) and invalidated on admin writes. `/features/me`, `/features/:key/start-trial`, `/sync/:key` (versioned docs, 409 on conflict).
* **Billing/payments**: plans (kobo, NGN) in `AppConfig.billing`; `billing.logic.ts` pure + tested (limits ₦50 … ₦5,000,000, ≤6 plans). Flow in root CLAUDE.md §4. `payments.service.settlePayment` is the only place that grants Premium: verifies with Paystack, checks amount+currency, atomically claims `applied`, extends `premiumUntil`, sends the receipt. `PAYSTACK_BASE_URL` is a test-only override ignored when `NODE_ENV=production`. Paystack calls send a User-Agent; failures log `[payments] initialize failed: <status> <message> | firewall page "<title>", Ray ID <cf-ray>, at <time> | body: <snippet>` (never the key). Admin `POST /admin/billing/test` checks the key (GET /bank) AND probes `POST /transaction/initialize` with amount 0 (Paystack answers 400 JSON, creates nothing) — on 2026-11-06 Paystack's firewall blocked POSTs from Render's shared outbound IPs while GETs passed. Checkout failure → 502 "Payments are temporarily unavailable…" (the app shows 502/503/504 server messages; 500 stays generic).
* **Webhook** `POST /api/v1/webhooks/paystack`: raw body, HMAC-SHA512 (`x-paystack-signature`), timing-safe compare; always 200 for valid signatures (idempotent).
* **Rate limiting**: `FailOpenRedisStore` (RedisStore subclass that never throws) + 1.5 s timeout + 20 s circuit breaker (+ `passOnStoreError:true` as a second net) — an Upstash outage must never take the API down. Logs ONE `[rate-limit] Redis unavailable …` line when it starts and `… Redis is back` when it ends (e2e-tested). Auth limiter counts failures only. Limiter key + audit IP = `utils/clientIp.ts` (production: `CF-Connecting-IP` → `True-Client-IP` → `req.ip`; Render's `req.ip` is a rotating proxy address, found 2026-11-07). Fail-open returns `totalHits: 1` (express-rate-limit 8 rejects 0 → ERR_ERL_INVALID_HITS). `config/redis.url.ts` forces TLS for `*.upstash.io` (a `redis://` URL used to give endless `ECONNRESET`), logs `[redis] connecting to <scheme://host:port>` (no password) + a warning for a wrong URL; the connection has an `error` listener (one line per distinct error). Startup grace `REDIS_STARTUP_GRACE_MS` (10 s): the Upstash TLS connect takes ~4 s on Render, so limiters wait for `ready` and stay quiet meanwhile (else a false "Redis unavailable" at every boot).
* **Team & roles (S5)**: roles user|tester|admin|owner (`services/roles.logic.ts`, `roles.service.ts` `roleOf`). `requireStaff` (owner/admin from the DB; a verified ADMIN_EMAILS account is ALWAYS owner = break-glass) + `can('perm')` on every admin route (`tests/admin-routes.test.mjs` fails on a route without it); `/admin/me` (`anyTeamMember`). Team API owner-only (`team.manage`, never grantable): GET/POST `/admin/team`, PATCH/DELETE `/admin/team/:id` — actor password re-check, not yourself, never the last owner, ADMIN_EMAILS owners fixed, target refresh tokens cleared, audit `team.*` with before/after. `PATCH /admin/users/:id {role: user|tester}` (users.write; plan=users.write, disabled=users.disable; team members refused). Tester/admin/owner = Premium-equivalent (`planForRole` in `protect` + `formatUser`) and every feature (`evaluateAccess`). `create-admin.ts` makes OWNERS; `migrate-roles.ts` (dry run / `--confirm`) for old admins.
* **Admin API** (`/api/v1/admin/*`): stats (incl. revenue), audit, config/features, billing (+test), payments, users (list/detail/patch/grant/revoke/restore/reset-trial/verify). Every mutation writes `AdminAudit`. (Roles/permissions redesign → docs/ADMIN_ROLES_PLAN.md.)
* **Pages**: `/`, `/verify-email`, `/reset-password`, `/payment/callback` are server-rendered HTML in `services/pages/pages.ts` (also used by e-mail links). E-mail links use `APP_URL`.
* **Account deletion (S7.1)**: `services/accountDeletion.service.ts` (`deleteAccount`) — Cloudinary files + Book/Annotation/Bookmark/Progress/UserData/UserFeature/Job deleted, Payments kept with `email:''`, audit `account.deleted_by_user` (no e-mail/IP), goodbye e-mail, then the User. App: `DELETE /users/me` {password} (authLimiter; wrong password = **403**, not 401, so the app does not refresh+retry). Web: `/delete-account` page → `POST /auth/delete-account/request` (same answer always, 1/min/account) → e-mail link `/delete-account/confirm?token=` (SHA-256 stored in `accountDeletionTokenHash`, 1 h) → `POST /auth/delete-account/confirm`. **Any new user-linked collection must be added to `deleteAccount`.**
* **App releases (S2)**: `AppRelease` (channel direct|play, version, versionCode unique per channel, downloadUrl https on github.com / readin.micbol.org / play.google.com, sha256, sizeBytes, notes, mandatory, minSupportedVersionCode, published, releasedAt). Public `GET /app/version?channel=&versionCode=` (cached 60 s, cleared on admin writes; unknown versionCode → never mandatory). Admin `GET/POST /admin/releases`, `PATCH /admin/releases/:id` (audit `release.*`). Rules pure in `appRelease.logic.ts` (`tests/app-release.test.mjs`). Not user-linked → nothing for `deleteAccount`.
* Library free limit = `billing.freeLibraryLimit` (default 10) — never hard-code 10.
* **Premium controls (S9.2)**: `BillingConfig` also has `trialDays` (0=off, once per account, never after a paid purchase), `reminders {enabled, steps[{offsetDays,inApp,email}]}` (default −5,−2,0,+3) and `marketing {headline, showPerDay, showSavings}`; `/config/public` adds `trialDays`, `headline`, `reminders` (in-app offsets) and per plan `perDayText`/`savingsText` (all pure in `billing.logic.ts`, `tests/premium.test.mjs`). User: `premiumKind` (paid|trial|gift), `premiumTrialUsedAt`, `premiumRemindersSent` (`offset@premiumUntilISO`, last 20), `emailReminders`. `/config/public` answers `Access-Control-Allow-Origin: *` without credentials (the website reads prices from the browser). App API `/billing/status`, `POST /billing/trial` (atomic), `PATCH /billing/reminders {email}`. `services/premiumReminders.service.ts` runs hourly (`PREMIUM_REMINDERS_INTERVAL_MS`, 0=off) + admin `POST /admin/billing/reminders/run`; claims the key BEFORE sending (exactly once, e2e + mutation tested); only the latest due step, ≤2 days late.

## When you add things
New model/route → controller + zod validation + auth/permission + audit (admin) + rate limit scope + test + `.env.example`/docs. Pure logic goes in `*.logic.ts` with a `tests/*.test.mjs`. Schema changes affecting existing users need a migration script in `src/scripts/` that is idempotent, plus a Mongo Atlas backup reminder to Michael. Keep API responses backward compatible with already-installed app versions (APKs in the wild cannot be force-updated instantly).
