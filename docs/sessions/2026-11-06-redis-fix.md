# 2026-11-06 — Redis (Upstash) errors on Render

Branch: `fix/redis-upstash` (from main)

## Asked
Michael deployed with the new Upstash URL; Render log still shows `Redis command timed out`, `ERR_ERL_INVALID_HITS`
and repeated `[ioredis] Unhandled error event: read ECONNRESET`. Also: stop dev servers (ask first before starting one),
list everything left to implement.

## Found
- `ECONNRESET` on every reconnect + first command timing out = the classic sign of a **plain-TCP connection to Upstash**
  (Upstash only accepts TLS). Happens when the URL starts with `redis://` instead of `rediss://`, or when the REST URL
  (`https://…`) is pasted. The code passed the URL to ioredis unchanged, so a one-letter slip broke Redis silently.
- `ERR_ERL_INVALID_HITS`: our fail-open store returned `totalHits: 0`; express-rate-limit 8 rejects 0.
- `Unhandled error event`: no `error` listener on the ioredis connection.
- Stopped the `site` Next dev server (port 3000). Memory: ask before starting dev servers.

## Changed
- `server/src/config/redis.url.ts` (new, pure): strips quotes, forces TLS for `*.upstash.io`, logs `scheme://host:port`
  only (never the password), plain-language warnings (redis://, REST URL, no password, unreadable).
- `server/src/config/redis.ts`: uses it, `tls: {}` when needed, one-line `[redis] connection problem: …` per distinct error,
  `[redis] connected` / `connected again`.
- `rateLimit.middleware.ts`: fail-open → `totalHits: 1`.
- Tests: `tests/redis-url.test.mjs` (7); e2e asserts no `ERR_ERL_INVALID_HITS` / `Unhandled error event`.

## Tested
- typecheck ✅, lint 0 errors ✅, unit tests ✅ (incl. 7 new), e2e 29/29 ✅; mutation (totalHits back to 0) → e2e fails ✅.
- NOT tested: the real Upstash connection (needs the secret URL — Michael checks the Render log after deploy).

## Part 2 — after merge (branch `fix/redis-startup-race`)
- Render log: `[redis] connecting to rediss://steady-prawn-193820.upstash.io:6379 (TLS)` → 4 s later `[redis] connected`.
  Live check: `RateLimit-Remaining` 199 → 198 → 197 on /config/public → **Redis works** (TLS fix confirmed).
- The remaining "Redis unavailable (Redis command timed out)" line = startup race: limiter loads its scripts at boot,
  the TLS connect takes ~4 s, the 1.5 s timeout fires first, breaker 20 s, then fine.
- Fix: `REDIS_STARTUP_GRACE_MS` (default 10 s): limiters wait for 'ready' before loading scripts and pass requests quietly
  while still connecting. e2e uses 0 (dead Redis). typecheck ✅ lint 0 errors ✅ unit ✅ e2e 29/29 ✅.
